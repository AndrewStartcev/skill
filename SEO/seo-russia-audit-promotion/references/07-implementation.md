# Внедрение: WordPress, 1C-Битрикс, frontend и сервер

## Общие правила
Сначала составь ТЗ с ожидаемым URL/HTTP/HTML/DOM, затем внедряй через staging, код-ревью и контрольный crawl. Не редактируй production без согласия, резервной копии и плана отката. SEO-изменения должны быть идемпотентными, покрывать все шаблоны и не ломать формы, оплату, поиск и локализацию.

## WordPress
- Убедись, что `Настройки → Чтение → Попросить поисковые системы не индексировать сайт` выключено на production; на staging исключение должно быть защищено доступом, а не только robots.
- Проверяй `wp_head()`, `wp_footer()`, `document_title_parts`/`pre_get_document_title`, `wp_robots`, `template_redirect` и генерацию canonical на всех шаблонах.
- Если используется SEO-плагин, не дублируй его вывод кастомным кодом. Выбери единый источник title, description, robots, canonical, JSON-LD, sitemap.
- Контролируй архивы, теги, страницы поиска, пагинацию, attachment URL, параметры, WooCommerce-категории/товары/вариации и снятые с продажи позиции.
- Кастомные ACF-поля и таксономии должны иметь серверный HTML-вывод для основного контента; `a href`, а не JS-only navigation.
- После смены постоянных ссылок — карта редиректов и обновление внутренних ссылок; не заменяй постоянные редиректы временными правилами.

## 1C-Битрикс
- Проверь `/bitrix/` и другие служебные пути в robots с учётом реальной структуры, не закрывая нужные публичные ресурсы.
- Используй штатные механизмы заголовков и мета (`SetTitle`, `SetPageProperty`, свойства разделов/элементов) последовательно; избегай нескольких противоречащих источников `title` и `canonical`.
- Проверь ЧПУ компонентов, дубли `index.php`/слешей/параметров, умный фильтр, постраничную навигацию, кеширование, composite mode и региональные версии.
- Sitemap должен отражать только нужные индексируемые URL; после импорта каталога перепроверь статусы товаров и canonical.
- При редиректах на уровне Nginx/Apache и в PHP не создавай циклы и цепочки; учитывай кеш и CDN.

## Frontend / SPA
- Проверь `view-source` и rendered DOM: виден ли основной контент и ссылки без пользовательского действия? При необходимости SSR/SSG или рендеринг на сервере.
- Сохраняй осмысленные адреса, корректные HTTP-статусы, `title`/`description`/`canonical`/robots в исходном HTML и работоспособную навигацию.
- `Schema.org` из данных CMS валидируй по схеме и по фактическому видимому содержимому; не вставляй вымышленные отзывы, рейтинги, цены.

## Серверные конфигурации и файлы
- `robots.txt`: в корне хоста; проверяй правила отдельно для production и staging. Не блокируй CSS/JS, необходимые для понимания страницы.
- `sitemap.xml`/`sitemap_index.xml`: доступный XML, правильные абсолютные URL, обновляемый `lastmod`.
- Nginx/Apache: постоянные редиректы, корректные 404/410, HTTPS, кеширование, сжатие и заголовки `X-Robots-Tag` для PDF/файлов при необходимости.
- Статические PDF: индексация по назначению; `X-Robots-Tag` или иная стратегия, если документ не должен участвовать в поиске; robots не защищает приватность.

## Приёмочные тесты
Для каждого затронутого шаблона: статус и конечный URL; canonical; robots/X-Robots; title/H1; HTML и rendered DOM; внутренние ссылки; sitemap; JSON-LD; мобильный UX; формы/корзина; 404 и редиректы. Прогони на URL с UTM, пагинацией, фильтрами и региональными версиями. Запиши до/после и план отката.
