# Сценарии применения скилла

## A. Новый коммерческий сайт
1. Бриф, цели, регион, интервью/факты.
2. Семантика и кластеризация интентов; sitemap и список типов страниц.
3. Для каждого типа: реальный текст, proof points, CTA, метаполя, связи с другими страницами.
4. Wireframes → токены и компоненты → hi-fi desktop/mobile → прототип.
5. Handoff и приемка по UX/a11y/SEO/performance.
**Результат:** страницы проектируются как связанная система, а не одна красивая главная.

## B. Редизайн действующего сайта без смены URL
1. Собери baseline и зафиксируй сильные органические страницы.
2. Сравни старые и новые блоки по смыслу; проверь, не исчезли ли цены, FAQ, контент, ссылки и региональные сигналы.
3. Сохрани URL/основной интент; любое существенное сокращение объясни и согласуй.
4. Проверь SEO-инварианты, HTML и аналитику до/после.
**Результат:** современный интерфейс без бесконтрольной потери поисковой полезности.

## C. Редизайн с новой структурой и URL
1. Полный URL inventory и page-to-page redirect map.
2. Определи keep / 301 / 404 / 410 / merge / split; проверь соответствие интентов.
3. Проектируй новые разделы вместе с навигацией и перелинковкой.
4. Тестируй 301 и canonical, sitemap, индексацию, аналитику, rollback.
5. Отслеживай критичные URL после релиза.
**Результат:** документированный переезд с контролем SEO-рисков.

## D. Сайт медицинской организации
1. Структура услуг, специалистов, филиалов, цен, способов записи, FAQ.
2. Факты только из проверенных материалов; никаких придуманных лицензий, врачей, результатов лечения и гарантий.
3. Экспертная/юридическая проверка медицинских утверждений и обязательных сведений.
4. Удобный мобильный сценарий записи, контакты, адреса, доступные формы.
5. SEO по интенту/региону, структурированные данные только по факту.
**Результат:** полезный и достоверный сайт с прозрачным путем записи.

## E. Каталог или интернет-магазин
1. Категории и фильтры по спросу; политика индексирования фасетов и сортировок.
2. Карточки с характеристиками, наличием, вариантами, доставкой/возвратом — по проверенным данным.
3. Empty states, сравнение, корзина, ошибки оплаты/форм.
4. Мобильная навигация, скорость каталога, изображения, structured data по правилам.
**Результат:** масштабируемые шаблоны без SEO-дублей и UX-тупиков.

## F. Заказ только на SEO-тексты и контент
1. Получи URL/тип страницы, регион, кластер и подтвержденные факты.
2. Составь outline и страницу в [матрице](../assets/page-content-matrix.csv).
3. Напиши Title, description, H1, hero, CTA, блоки, FAQ, alt-план, внутренние ссылки.
4. Отметь неподтвержденные заявления, предложи короткие версии для карточек/мобильного.
5. Проверь тексты в контекстах дизайна и CMS.
**Результат:** готовый к редактуре контент-пакет, а не механическая SEO-простыня.

## G. Аудит чужого Figma-макета
1. Установи цель и статус: concept, approved, ready for dev.
2. Проверь IA/контент, мобильные фреймы, Auto Layout, variables, components, states.
3. Найди риски: недоступные CTA, слабая иерархия, пустые блоки, невозможность сверстать, отсутствие SEO-страниц.
4. Отчет: issue → frame/layer → наблюдение → влияние → исправление → приоритет → acceptance criteria.
**Результат:** проверяемый backlog исправлений.

## Формат итогового ответа
- Что проверено и какие источники доступны.
- Что подтверждено, что гипотеза, какие данные отсутствуют.
- Приоритетные решения с ожидаемым эффектом и риском.
- Готовые артефакты и ссылки на них, если действительно созданы.
- Следующий конкретный шаг и критерии приемки.
