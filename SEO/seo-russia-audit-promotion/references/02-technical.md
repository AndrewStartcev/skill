# Технический SEO-аудит: чек-лист и логика

## A. Доступность и HTTP
1. Сопоставь HTTP/HTTPS и www/non-www; выбери целевую версию, проверь последовательные 301/308 без циклов, цепочек и потери параметров там, где они нужны.
2. Проверяй 200 для индексируемых страниц, 404/410 для удалённых без замены, 301 для переехавших, 5xx/тайм-ауты и soft-404 для пустых страниц. Не отправляй все 404 на главную.
3. Проверь TLS, сертификат, mixed content, доступность мобильным пользователям, CDN/WAF, стабильность TTFB и ошибочные блокировки роботов.
4. Сопоставь серверный HTML и rendered DOM для JS/SPA. Важный контент, навигация, title, canonical и ссылки должны быть доступны роботам; SSR/SSG/пререндеринг — варианты решения, не обязательный универсальный рецепт.

## B. Индексирование: четыре разных вопроса
**Discovery** — URL известен? **Crawl** — робот может получить? **Index** — попал в индекс? **Rank** — показывается по запросам? Наличие в sitemap и HTTP 200 не гарантирует индексацию и показы.

- `robots.txt` управляет обходом, не является механизмом конфиденциальности и не гарантирует удаление URL из выдачи. Для чтения `noindex` бот должен иметь возможность получить страницу.
- `meta robots` / `X-Robots-Tag`: проверяй значения для нужного робота; `noindex` на коммерческой посадочной — P0/P1; `nofollow` — не синоним запрета индексации.
- `rel="canonical"` — подсказка о предпочтительном дубле, не редирект и не гарантированное исключение. Сравни canonical с конечным 200, доступностью, языком, содержимым, sitemap и внутренними ссылками.
- Sitemap: только актуальные канонические индексируемые URL, корректный XML и `lastmod` при реальных изменениях; проверь 200, лимиты, вложенные sitemap, локаторы из `robots.txt` и отчёты обработки.
- Сравни множества: важные URL по бизнесу, sitemap, crawl, органические посадочные, индекс/исключения в Вебмастере/GSC, логи ботов. Разбери причины расхождений.
- Не смешивай `Disallow`, `noindex`, `canonical`, 301 и 404: у каждого разная задача и побочные эффекты.

## C. Архитектура и дубли
- Схема URL: ЧПУ, единая политика слешей/регистра/параметров, UTM и сортировок, не допускать бесконечных пространств URL.
- Фильтры: отдельные SEO-посадочные только для подтверждённого спроса и уникальной полезности; остальные комбинации контролировать стратегией обхода и каноникализации с учётом поисковика.
- Пагинация: доступные HTML-ссылки на страницы и товары; не canonical все страницы на первую автоматически. `rel="prev/next"` не является универсальным механизмом индексации.
- Проверить дубли title/H1/description, пустые карточки, тонкие страницы, пересекающиеся региональные страницы, поиск по сайту, теги и архивы.
- Внутренняя перелинковка: осиротевшие URL, глубина, хлебные крошки, анкоры, ссылки в HTML (`a href`), битые внутренние ссылки, циклические редиректы.
- Локализация: `lang`, корректный `hreflang` (если несколько языков/региональных версий), взаимные ссылки и self-reference где применимо; IP-редиректы не должны скрывать страницы от робота.

## D. HTML, контент, структурированные данные
- Уникальные информативные `title`, осмысленный H1 и иерархия H2–H6; `meta description` — для сниппета, не гарантированный фактор ранжирования.
- Основной текст и коммерческие элементы видимы и доступны, без keyword stuffing; изображения имеют полезные `alt` там, где содержат информацию.
- JSON-LD/Schema.org: валидность синтаксиса, соответствие реальному видимому контенту, поддержка конкретным поисковиком и типом результата; разметка не гарантирует расширенный сниппет. Проверяй BreadcrumbList, Organization/LocalBusiness, Product/Offer, Article и др. только по применимости.
- Важные файлы: `/robots.txt`, sitemap/sitemap index, `.htaccess` или конфигурация Nginx, шаблоны `head`, правила URL, фиды (по потребности), `ads.txt` только при рекламной модели и не как SEO-фактор.

## E. Скорость и мобильность
- Проверяй реальные шаблоны на мобильном: viewport, текст, кликабельность, перекрытия, формы, контент и навигацию.
- Используй CrUX/полевые данные и Lighthouse/PSI лабораторные данные отдельно. CWV: LCP, INP, CLS; не объявляй «100/100» самоцелью или гарантией ранжирования.
- Диагностируй ресурсы: изображения/форматы/размеры, кеш, шрифты, критический CSS, JS, третьи стороны, сервер. Исправления сверяй с UX и конверсией.

## F. Логи и масштабы
- По логам: реальные запросы поисковых ботов (проверка обратного DNS по официальным рекомендациям), статусы, частота, время ответа, разделы и расход обхода.
- Для большого сайта — отдельные отчёты по шаблонам и сегментам; тестировать URL с параметрами, региональные версии, товары в наличии/нет.
- Учитывать мобильный рендеринг, JS-гидратацию, кэш/CDN и ответ сервера с разными User-Agent без клоакинга.

## G. Матрица выбора
| Цель | Обычно подходит | Осторожно |
| --- | --- | --- |
| Перенос URL с эквивалентным содержимым | 301/308 + обновить ссылки | Не массово на главную |
| Дубликат, который нужен пользователям | canonical на предпочтительный URL | Каноникал может игнорироваться |
| Убрать страницу из индекса, оставить доступной | noindex с доступным обходом | Disallow может скрыть noindex от робота |
| Ограничить обход мусорных URL | robots.txt + архитектура параметров | URL всё ещё может появляться в поиске |
| Удалённая без замены | 404/410 | Не возвращать 200 с «не найдено» |
| Переезд на HTTPS | постоянный редирект + каноникал + sitemap | Смешанные ресурсы и цепочки |

## H. Верификация
Повторно проверь конкретный URL и шаблон на production, заголовки и конечный HTML; затем сверяй Вебмастер/GSC после переобхода. Фикс в коде ≠ мгновенное изменение индекса. Для каждого обнаружения сохраняй URL, код ответа, фрагмент/скриншот или экспорт и способ воспроизведения.
