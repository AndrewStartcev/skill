# Рабочий процесс SEO-проекта

## 1. Бриф и рамки
Зафиксируй: тип бизнеса, целевые действия, маржинальность/ценность лида, приоритетные товары/услуги, географию, языки, конкурентов, ограничения по разработке и юридические ограничения. Выясни, что считается органикой в используемой системе аналитики и какие цели корректно настроены. Для миграций — полный список старых и новых URL и дату переключения. Для падения — дату начала, историю релизов, поисковые обновления как гипотезу, изменение спроса и конкурентов.

## 2. Инвентаризация источников
| Источник | Что даёт | Ограничение |
| --- | --- | --- |
| Публичный HTTP/HTML crawl | Статусы, метатеги, ссылки, архитектуру | Не показывает фактический индекс и все JS-состояния |
| Рендеринг браузером | DOM после JS, UX, ошибки консоли | Может отличаться от робота |
| Яндекс Вебмастер | Обход, исключения, запросы, нарушения, регион | Нужен подтверждённый доступ |
| Яндекс Метрика | Визиты, источники, цели, e-commerce | Требует проверки корректности счётчика и атрибуции |
| Google Search Console | Показы, клики, индексация, URL Inspection | Частичная/агрегированная статистика |
| Серверные/CDN логи | Фактические запросы роботов и коды | Нужна фильтрация ботов, PII и полнота логов |
| PageSpeed Insights/CrUX | Лабораторные и полевые показатели | Полевых данных может не быть |
| CRM/коллтрекинг | Качество лидов, сделки, выручка | Атрибуция, согласие, персональные данные |
| Сервисы семантики | Спрос, подсказки, конкурентные кластеры | Частотности и позиции приблизительны |

Не считай выборку из 50 страниц полным аудитом сайта на 50 000 URL. Стратифицируй: главная, категории, листинги, карточки, статьи, региональные, фильтры, пагинация, 404, служебные.

## 3. Этапы проекта
**0–7 дней — диагностика и защита индекса.** Снять baseline; устранить P0: недоступность, `noindex` на важных страницах, глобальные блокировки, массовые ошибки редиректов, взлом. Проверить аналитические цели и критические шаблоны.

**8–30 дней — фундамент.** Нормализовать индексируемые URL, canonical/редиректы, sitemap, внутренние ссылки, шаблоны title/H1, скорость/мобильность, коммерческие блоки. Сформировать карту семантики и ТЗ.

**31–60 дней — покрытие спроса.** Обновить приоритетные посадочные, категории, карточки, экспертные материалы; устранить каннибализацию, улучшить сниппеты и внутреннюю навигацию; настроить локальные карточки.

**61–90 дней — масштабирование и проверка.** Расширить семантические кластеры, провести тесты гипотез, оценить эффект по сегментам, повторить технический аудит, скорректировать roadmap.

Сроки ориентировочные: зависят от размера сайта, ресурсов и частоты переобхода. Не обещай срок выхода в ТОП.

## 4. Приоритизация
P0 — критическая потеря доступа/индекса/безопасности/аналитики для основных шаблонов; исправить немедленно с откатом.
P1 — массовая потеря охвата или конверсии; ближайший спринт.
P2 — значимый потенциал в контенте/UX/перелинковке; плановые спринты.
P3 — локальные улучшения и эксперименты.

Для сравнения задач используй прозрачную оценку: `ожидаемый эффект × охват × уверенность / (трудозатраты + риск)`. Не превращай балл в точный прогноз трафика. Всегда отмечай зависимость от разработки/контента/юристов.

## 5. Сценарии
- **Новый сайт:** спрос → архитектура → шаблоны → техническая доступность → аналитика → запуск → индексация → контент.
- **Действующий сайт:** baseline → аудит → сегментные гипотезы → спринты → измерение.
- **Падение:** сравнение одинаковых сезонных окон → сегментация по поисковику/устройству/региону/URL → проверка релизов и индекса → спрос и SERP → проверка гипотез.
- **Переезд:** до релиза карта 1:1, staging закрыт, новая структура; после релиза постоянные 301, canonical/sitemap/internal links, проверка важных URL и мониторинг 4xx/5xx.

## 6. Контроль качества
Результат должен различать: `факт` (проверенный ответ сервера), `интерпретация` (что он значит), `гипотеза` (почему влияет), `рекомендация` (что менять), `проверка` (как принять). Указывай дату/регион/устройство/выборку/источник. Сохраняй только обезличенные материалы.
