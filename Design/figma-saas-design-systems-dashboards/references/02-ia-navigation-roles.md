# 02. Информационная архитектура, навигация и права

## Сущности и маршруты
Составь object model: сущность → атрибуты → связанные сущности → статусы → действия → ограничения. Для каждой сущности отдели список, detail, форму создания/изменения, историю и связанные разделы.

Типовая карта SaaS:
- **Обзор**: задачи на сегодня, исключения, контекстные KPI, следующие шаги.
- **Рабочие сущности**: список / board / detail / edit, согласно форме работы.
- **Аналитика**: метрики, сегменты, drilldown, параметры периода и экспорта.
- **Команда и доступы**: пользователи, приглашения, роли, ограничения.
- **Настройки**: организация, уведомления, интеграции, тариф и биллинг.

Не навязывай эту карту, если модель продукта другая.

## Навигация
- Сайдбар — повторяющиеся предметные разделы; верхняя панель — контекст, организацию, глобальные действия и уведомления по фактической потребности.
- Названия по лексике пользователей, не техническим названиям таблиц БД.
- Текущий раздел, вложенность, активная вкладка и выбранный объект видимы явно.
- Контекстные действия — ближе к объекту; глобальное создание — в предсказуемом месте.
- Поиск различай: глобальный по сущностям и локальный внутри текущего набора.
- Переключение организации/рабочего пространства должно менять контекст осознанно; показывай, где сейчас пользователь.

## Права и роли
Матрица для каждого критичного действия: `view / create / edit / export / delete / approve / manage members`. Для отсутствия доступа предусмотрены отдельные решения:
1. Скрыть действие, если раскрытие самого существования данных недопустимо.
2. Показать disabled + объяснение, если знание о функции полезно.
3. Вывести permission/error screen, если пользователь попал на URL без прав.

Не путай permission error с пустым списком. Не изображай в макете доступ к чужим данным.

## Прототипирование flows
Опиши успешный маршрут и альтернативы: отмена, отказ, ошибка сети, недостаточно прав, конфликт изменений, несохранённый ввод, пустая выборка. Для необратимых действий нужна явная модель подтверждения и предполагаемого восстановления.

**Проверка:** пользователь может сказать, где он, что видит, что сделать дальше и как вернуться. См. [экранную спецификацию](../assets/screen-spec.md).
