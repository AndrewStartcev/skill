# Design QA / handoff — контрольный чек-лист

## Продукт и сценарии
- [ ] Пользовательские роли и задачи зафиксированы.
- [ ] Для каждой приоритетной операции есть начало, успех, ошибка, восстановление.
- [ ] Важные действия не скрыты только за hover.
- [ ] Удаление и bulk-операции показывают объём и последствия.
- [ ] Нет утверждений о реальных метриках/исследованиях без подтверждения.

## Design system
- [ ] Component inventory и назначение токенов описаны.
- [ ] Variables/alias/modes используются осмысленно, нет случайных цветов.
- [ ] Main components и instances не заменены разрозненными копиями.
- [ ] Components имеют применимые default/hover/focus/disabled/loading/error.
- [ ] Auto Layout и resizing выдерживают длинные подписи.

## SaaS и данные
- [ ] KPI имеют единицы, определения, периоды, источники и свежесть.
- [ ] Таблицы: сортировка, фильтры, поиск, выбор строк и bulk semantics.
- [ ] «Нет данных», «0», «нет прав» и «ошибка» — разные состояния.
- [ ] Графики не искажают шкалы и имеют доступный текстовый/табличный эквивалент как требование.

## Адаптив и доступность
- [ ] Широкая и узкая конфигурации проверены.
- [ ] Focus states и порядок клавиатурного обхода задокументированы.
- [ ] Статусы читаются без опоры только на цвет.
- [ ] Контраст проверен для всех предусмотренных тем.
- [ ] Язык, даты, часовые пояса, валюты и длинные строки проверены.

## Handoff
- [ ] Есть ссылки на Figma frames и main components, версия и статус.
- [ ] Прописаны token names, component states, responsive, interactions и ограничения прав.
- [ ] Неопределённые продуктовые решения явно помечены.
- [ ] QA-замечания имеют приоритет, причину, исправление и критерий приёмки.
