# 09. SaaS-паттерны, сценарии и состояния

## Основные потоки
Выбирай для продукта:
- First-run / onboarding: создание рабочего пространства, приглашения, первая ценность, отказ от опциональных шагов.
- Вход/выход и восстановление доступа: состояния, но без проектирования логики хранения секретов.
- CRUD: список → карточка → создание/редактирование → валидация → сохранение → результат.
- Поиск/фильтр/сортировка → результаты → открытие объекта → сохранение контекста.
- Одобрение/отказ, передача ответственности и история изменений.
- Роли и приглашения: кому виден объект, кому разрешено действие.
- Работа с настройками, биллингом и тарифами — когда реально входит в продукт.
- Несохранённые изменения, конкурирующие правки, конфликт версии, частичная потеря сети.

## State inventory
| Состояние | Сообщение | Действие | Figma-артефакт |
| --- | --- | --- | --- |
| Loading | Что обновляется | Wait/Cancel, если есть | Skeleton/progress |
| Empty first use | Почему пусто, что создать | Конкретный CTA | EmptyState/new |
| Empty after filters | Нет совпадений | Сброс фильтров | EmptyState/filtered |
| Error recoverable | Что не удалось | Повторить | Alert/error |
| Error blocking | Почему нельзя продолжить | Альтернативный путь | Full-page/error |
| No permission | Ограничение доступа | Запросить доступ, если предусмотрено | Permission |
| Success | Что именно выполнено | Перейти к объекту | Toast/inline/banner |
| Partial success | Что прошло/не прошло | Посмотреть ошибки | MixedResult |
| Offline/stale | Данные могут устареть | Обновить | Banner/stale |

## UX закон для сложных операций
После действия пользователь должен понять три вещи: принято ли действие, что изменилось, может ли он его отменить/исправить. Прогресс фоновых задач не должен имитировать мгновенный успех.

## Prototyping в Figma
1. Поставь `Start`, happy path, минимум один failure path и recovery.
2. Различай hotspot/interactive area, overlay, back, return to list.
3. Отражай переходы статусов в имени фрейма или аннотации.
4. Укажи trigger, expected state, data mutation, role preconditions.
5. Предусмотри keyboard/focus order как спецификацию к handoff.

## Anti-patterns
Пустое состояние «Nothing here» без действия; error и permission одним экраном; кнопка «Удалить» без контекста; модальные окна поверх модальных окон; путаница между закрытием и сохранением; индикатор «Успешно» до подтверждения результата.
