# 08. Визуализация данных для SaaS

## Перед выбором графика
Уточни: решение пользователя, точный набор данных, шкалу/единицы, период и частоту, сегменты, нижнюю/верхнюю границу, пропуски, уровень доверия. Вначале определи смысл, затем подбери chart type.

| Задача | Базовая форма | Осторожность |
| --- | --- | --- |
| Динамика во времени | Line / area | Ложная сглаженность, неполный текущий период |
| Сравнить категории | Horizontal bar, сортировка | Усечённая ось для столбцов, слишком много категорий |
| Доли от общего | 100% stacked bar | Сумма и категории должны быть определены |
| Распределение | Histogram / box plot | Непонятные бины и выбросы |
| Взаимосвязь показателей | Scatter | Корреляция ≠ причинность |
| Этапы процесса | Funnel с исходными числами | Непоследовательные когорты, непонятные переходы |
| Точные значения | Table | Не заменять графиком то, где важна точность |

Pie/donut — только для немногих различимых долей, когда это действительно облегчает оценку. Не использовать круговую диаграмму для временного ряда или большого числа сегментов.

## Обязательная анатомия chart
- Заголовок, вопрос и контекст (чей/какой показатель).
- Период, единица и источники данных.
- Оси/деления, форматы чисел/дат, легенда/серии.
- Явные значения при фокусе/tooltip, полезные подписи.
- Свежесть данных/срез, если влияет на интерпретацию.
- Empty / loading / error / no-permission / partial-data.
- Доступная табличная альтернатива для чтения точных значений на уровне спецификации интерфейса.

## Визуальная честность
1. Столбики от нуля при обычном сравнении абсолютных величин. Если нужен иной масштаб, явно обозначь.
2. Не меняй интервал выборки незаметно при сравнении периодов.
3. Ноль, отсутствие записи, неизвестно и недоступно — разные состояния.
4. Цвет не единственный канал: метки, паттерны, подписи и порядок серий.
5. Используй единую цветовую семантику для одинаковых серий на разных экранах.
6. Статусы «плохо» и «хорошо» зависят от показателя: рост отказов обычно не равен росту выручки.

## Интерактивность в Figma
Покажи prototype для смены периода, hover/focus над серией, скрытия/выбора серии, drilldown к исходным записям, работы фильтров, отката фильтра. Укажи, какие возможности реализуются разработкой (например, доступность keyboard chart), а не обещай их реализацию средствами статичного дизайна.

**QA:** протестируй отрицательные и большие значения, длинные названия, одну точку, нулевую выборку, неполный последний период, 15 серий, узкий viewport. Не увлекайся декоративным 3D.
