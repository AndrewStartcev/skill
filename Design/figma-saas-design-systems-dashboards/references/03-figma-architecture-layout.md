# 03. Архитектура Figma и адаптивный layout

## Figma file organization
Разделяй рабочие страницы по назначению: `00 Cover`, `01 Foundations`, `02 Components`, `03 Patterns`, `04 Screens Desktop`, `05 Responsive`, `06 Prototype Flows`, `99 Archive`. Пронумерованные названия — пример, не догма. Используй Sections для групп ревизий и сценариев, избегай непомеченных «Frame 238».

Имена структурированных слоёв: `AppShell/Sidebar`, `Navigation/Item`, `Dashboard/KPI`, `DataTable/Row`. На компоненте отражай **семантическую роль**, не координаты или цвет. Для состояний — properties и variants, не отдельные клонированные страницы без связи.

## Отступы и типографика
- По умолчанию применяй шаг 4 px: 4, 8, 12, 16, 24, 32, 40, 48. Это рабочая шкала, не универсальный стандарт.
- Для плотного B2B-интерфейса проектируй компактный и стандартный density modes при необходимости; уменьшение высоты не должно ломать удобство нажатия.
- Определи max-width области, ширины панелей, минимальную ширину content/card/table.
- Типографика через styles, содержимое через текстовые компоненты; табличные числа желательно с табулярными цифрами.

## Auto Layout и resizing
- Вложенный Auto Layout для shell → content → toolbar → group → component.
- Выбирай Hug / Fill / Fixed осознанно; задавай min/max где применимо.
- Используй wrap, gap, padding и alignment, если поддерживаются текущей версией Figma.
- Constraints полезны для элементов вне auto layout; не смешивай случайно несовместимые стратегии.
- Перепроверь длинную локализацию, 200% zoom/text resizing в реализованном продукте; в Figma хотя бы демонстрируй дизайн при увеличенном тексте.

## Адаптивные контрольные точки
Не делай «магические» брейкпоинты без причины. Покажи реальное поведение как минимум при широком desktop, рабочем ноутбуке и узком viewport; mobile — если это пользовательский сценарий.
- Sidebar: expanded → collapsed → drawer или иной выбранный паттерн.
- Header/toolbar: перенос строк, secondary actions в overflow; ключевую операцию не прятать.
- KPI: число колонок меняется по доступной ширине, но порядок по значимости сохраняется.
- Большие таблицы: осмысленная горизонтальная прокрутка, фиксирование идентификаторов при необходимости, не автоматическая потеря колонок.
- Dialog: на узкой ширине — подходящий sheet/fullscreen, с доступной отменой.

## Design QA внутри Figma
Проверь при разных ширинах: нет разрыва Auto Layout, обрезанных CTA, случайных fixed-height контейнеров, detach компонентов, расходящихся styles и токенов. Зафиксируй макетное поведение каждого сложного блока.
