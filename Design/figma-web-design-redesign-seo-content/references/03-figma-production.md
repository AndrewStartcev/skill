# Figma: профессиональный рабочий процесс и практические приемы

## Организация файла
Используй понятные страницы: 00 Cover / Readme, 01 Research, 02 IA & Wireframes, 03 Foundations, 04 Components, 05 Screens, 06 Prototype, 07 Handoff, 99 Archive. Это пример, адаптируй под проект. Архив отделяй от актуального макета; помечай статус «Draft / Review / Ready for dev», владельца и дату.

Имена фреймов должны раскрывать шаблон, устройство и состояние: «Service / Mobile / Default», «Form / Desktop / Error». Имена компонентов — по назначению, не «Group 82». Для состояний и размеров используй свойства компонентов, не копии сотен фреймов.

## Foundations
- Цветовые роли: brand, text, surface, border, success, warning, danger, focus; зафиксируй light/dark только при реальной потребности.
- Типографика: семейства и начертания с лицензиями, размеры, межстрочные интервалы, веса, допустимая длина строки, стили H1/H2/body/caption. Проверяй кириллицу и символы валюты.
- Отступы и сетки: шкала (например, 4/8), container max-width, поля, колонки и gutters. Шкала — эвристика, а не стандарт.
- Радиусы, тени, иконография, motion, ограничения по изображениям.
- Переменные Figma (variables), modes и styles: семантические токены поверх базовых; при наличии библиотеки переиспользуй ее, а не плодить дубль.
- Для передачи в код подготовь таблицу «Figma token → CSS custom property / design token».

## Auto Layout и адаптивность
- Применяй Auto Layout к группам со смысловыми отношениями (строки, карточки, формы, секции). Выбирай vertical/horizontal/grid по содержанию.
- Настраивай padding, gap, alignment, wrapping, min/max sizes, fixed/hug/fill в соответствии с контекстом. Учитывай, что Figma — модель, а не браузерный CSS.
- Constraints применяй там, где они действительно нужны; не компенсируй отсутствие Auto Layout ручными координатами.
- Проверяй не только desktop и mobile, но и промежуточную ширину, увеличение шрифта, длинные подписи, многострочные CTA, пустые и очень длинные карточки.
- Протестируй реальный контент на русском и неидеальные данные: длинное имя услуги, двухстрочная цена, отсутствие фото, много FAQ.

## Компоненты
- Создай примитивы: button, link, input, textarea, select, checkbox, radio, badge, accordion, modal, toast, card, breadcrumb, tabs, header/footer, navigation.
- Разделяй свойства **type / size / state**, а не одну комбинированную строку «Primary Large Hover».
- Используй component properties (text, boolean, instance swap), variants, nested instances и slots по необходимости. Не делай variants ради каждого текста.
- Покажи интерактивные состояния и keyboard focus, валидацию, loading и disabled; укажи, что реализуется кодом.
- Сохраняй связь экземпляров с master-компонентами; detach только с обоснованием.

## Прототип и micro-interactions
Собери кликабельные маршруты для ключевых задач: меню, карточка, фильтр, форма, подтверждение. Для сложных сценариев подпиши условия перехода. Не считай Figma-прототип полноценным тестом реальной клавиатуры, screen reader или сетевого поведения.

## Handoff в разработку
- Маркируй актуальные фреймы Ready for dev и фиксируй версии/даты.
- Добавь пояснения для breakpoints, sticky, overflow, keyboard, ошибок и empty-state.
- Используй Dev Mode, когда он доступен на тарифе и у команды есть права; без него остаются спецификации и inspect-возможности, не обещай платные функции всем.
- Экспортируй только необходимые изображения/иконки, сохраняй SVG семантику и корректные лицензии; не экспортируй весь экран как одну картинку.
- Не принимай автогенерированный CSS/HTML из Figma за готовый production-код; верстка должна быть семантичной, адаптивной и тестируемой.

## Практические приемы
- **Shift+A:** Auto Layout для выбранных элементов.
- **Компонент вместо копипаста:** одно исправление распространяется на экземпляры.
- **Переменные вместо ручных цветов:** смена темы и ребрендинг без массовой правки.
- **Реальные тексты до финального UI:** сразу выявляют переполнение и слабую структуру.
- **Экран для QA с edge cases:** максимальная длина заголовка, пустые поля, длинные кнопки, ошибка формы.
- **Таблица статусов:** фиксирует готовность страниц и открытые вопросы.
- **Design-to-code карта:** компонент Figma ↔ шаблон CMS ↔ класс/BEM ↔ источник контента.

## Контроль качества Figma-файла
Проверь отсутствие случайных detached instances, скрытых устаревших фреймов в зоне handoff, локальных стилей-дубликатов, непонятных названий, незакрепленных шрифтов и критических блоков с абсолютным позиционированием.
