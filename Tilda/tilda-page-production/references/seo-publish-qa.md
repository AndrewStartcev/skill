# SEO, публикация и приёмка Tilda

## Настройки SEO для каждой страницы

1. **URL:** уникальный человекочитаемый slug в настройках страницы. Перед сменой существующего адреса проверь внешние ссылки и необходимость 301.
2. **Title / Description:** отдельные уникальные значения; проверь Page Settings → General и SEO → Customize search results preview, если переопределено. После дублирования не оставляй метаданные исходной страницы.
3. **H1:** один основной заголовок страницы; логичные H2/H3 для остальных секций; не заменяй H1 несколькими декоративными надписями.
4. **Изображения:** релевантные alt для содержательных изображений; оптимальный вес/размер без визуальных артефактов.
5. **Соцсети:** при необходимости настраивай Social media preview, OG-обложку и описание.
6. **Индексация:** согласованные черновики не должны быть случайно открыты поисковикам. Проверяй настройки страницы, robots и соответствующий способ защиты. Помни: noindex — не механизм контроля доступа.
7. **Структурированные данные:** добавляй только там, где это требуется, и не объявляй сущности/рейтинги, которых нет на странице. Хлебные крошки как интерфейс и BreadcrumbList как JSON-LD — разные задачи.

Для визуальных хлебных крошек проверь существующий блок; в библиотеке Tilda есть ME605. Сохраняй дизайн образца и проверяй каждый уровень и ссылку.

## Публикация ≠ сохранение

- В редакторе операция Save не делает новую версию видимой пользователям.
- После изменений нужно нажать Publish и открыть **публичный URL**, указанный Tilda.
- При редактировании каталога повторно опубликуй и каталог; аналогично проверяй изменения в Header/Footer (официальные инструкции могут требовать перепубликации страниц).
- Не нажимай «Publish all» на проекте с черновиками только для обновления пары страниц.
- Если контент после публикации старый, обнови страницу и исключи кеширование, не называя результат проверенным заранее.
- Для «должно быть опубликовано N страниц» ожидаемый факт — N доступных публичных URL, а не N вкладок редактора.

## Чек-лист после публикации

- [ ] Публичный URL открывается без авторизации и возвращает успешный HTTP-ответ.
- [ ] Правильные H1, title, description, язык и адрес страницы.
- [ ] Порядок всех секций соответствует эталону; сырого текста внизу нет.
- [ ] Все тексты, цены, изображения и ответы FAQ совпадают с источником.
- [ ] Десктоп/планшет/мобильные версии не имеют наложений.
- [ ] Кнопки, карточки каталогов, меню, хлебные крошки, якоря работают.
- [ ] Форма протестирована только безопасной согласованной тестовой отправкой, результат подтверждён (без спама в боевые интеграции).
- [ ] Индексирование настроено по требованию; noindex для черновиков.
- [ ] Изменённые связанные страницы и общие элементы обновлены и опубликованы.
- [ ] Итоговый список URL и количество страниц совпадают с ТЗ.

## Быстрая техническая проверка

Для доступных публичных страниц можно запускать:
~~~bash
node scripts/audit-pages.mjs assets/page-matrix.example.json
~~~

Это проверяет HTTP, title, description, H1, robots/noindex и обязательные ссылки из JSON-манифеста. Скрипт **не** умеет проверять визуальный дизайн, интерактивные формы, Zero Block, responsive layout, JavaScript-рендеринг и соответствие Figma; всё это проверяй в браузере.

## Формат краткой сдачи

| Показатель | Факт |
| --- | --- |
| Создано | число |
| Опубликовано | число |
| Черновики | число |
| Каталоги и общие блоки | URL и что обновлено |
| QA | размеры экранов, переходы, формы, метаданные |
| Открытые проблемы | конкретные блоки и причины |

Ссылки в отчёте — на реальные публичные страницы. Не выдавай редакторские URL за готовый сайт.
