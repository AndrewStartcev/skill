# Шаблоны, контент и тиражирование страниц

## 1. Сначала найти правильный эталон

Проверяй точный адрес редактора, ID и фактический дизайн, а не только название страницы. Если источник не найден, изучи список страниц проекта и запроси уточнение **только при реальной неоднозначности**. Зафиксируй, какие блоки используются и в каком порядке. Не подменяй эталон похожим.

Если задача — правки в существующих блоках, редактируй **эти блоки**. Не создавай новый блок «для простоты» и не переносись в конец страницы с сырым текстом.

## 2. Карта соответствия контента и блоков

Перед сборкой составь отображение «раздел согласованного документа → существующий блок Tilda → способ замены → ожидаемый результат».

| Поле документа | Блок страницы | Разрешённая операция | Проверка |
| --- | --- | --- | --- |
| Первый экран | Обложка исходной страницы | Заменить H1, подзаголовок, картинку и CTA | Композиция не изменилась |
| Для кого / преимущества | Карточки или текстовые колонки | Заполнить повторяющиеся элементы | Нет необработанного текста |
| Программа / этапы | Шаги, таймлайн, список | Сопоставить каждый пункт с элементом | Порядок сохранён |
| Стоимость | Согласованный тарифный блок | Заменить значения и подписи | Ничего не придумано |
| FAQ | Аккордеон / существующий FAQ-блок | Заменить вопросы и ответы поштучно | Все пункты присутствуют, раскрываются |
| Запись | CTA/форма | Обновить ссылку, проверять отправку | Конверсионный путь рабочий |

Длинный текст нельзя просто приклеить снизу, если для него предусмотрен конкретный блок. Если количество пунктов стало иным, **дублируй или аккуратно адаптируй элементы в том же визуальном стиле**, затем проверь их на всех устройствах. Если блок физически не поддерживает нужное количество элементов, предложи эквивалентное решение на основе существующих компонентов, а не молча меняй макет.

## 3. Дублирование в Tilda

Согласованную страницу дублируют через **Page Settings → Actions → Duplicate page**. Затем на дубликате:
1. Сразу присвой новое имя и уникальный URL/slug в настройках страницы.
2. Сверь секции с источником и замени поля через Content, сохраняя Block Settings, типографику, сетки, карточки и отступы.
3. При необходимости копируй отдельные **уже оформленные блоки** через меню блоков. Не изменяй эталон ради новой страницы.
4. Проверь изображения, alt, CTA, иконки, анкоры и другие ссылки, унаследованные от шаблона.
5. Проверь, что на странице не остались исходные цены, даты, названия, формы или FAQ.
6. Назначь отдельные SEO Title / Description / social-preview, если они предусмотрены.
7. Проверь адаптив и опубликуй по правилам задачи.

Редакторский URL вида tilda.ru/page/?pageid=... — **не публичная ссылка**. Для каталога, меню и отчёта используй опубликованный URL.

## 4. Многостраничный выпуск

При большом объёме работ сначала собери:
- одну эталонную страницу **каждого отличающегося типа**;
- каталог с готовой карточкой (если он есть);
- один образец статьи с оглавлением, когда требуется.

Проверяй типы отдельно: услуга ≠ статья ≠ каталог. Только затем тиражируй. Для каждого URL храни статусы «не начата», «в работе», «проверена», «опубликована», «заблокирована» и результаты приёмки.

В массовой работе с согласованным контентом допустимы исправления явных опечаток и пунктуации, но не смысловая редактура. Если требуется изменить структуру, отличающуюся от утверждённой, зафиксируй разницу и согласуй.

## 5. Каталоги и связанные страницы

- Размещай новые карточки **в существующей сетке и с существующими стилями**, не создавай дублирующий каталог в другом месте.
- Указывай только реально опубликованные URL.
- Проверь обложки и пропорции исходного шаблона, название, hover, кнопку, мобильную укладку.
- Для статьи связывай категорию, каталог/блог, оглавление и якоря. Якорь должен существовать на целевой странице.
- Не удаляй старые карточки или страницы без прямого поручения.

## 6. Отказоустойчивое выполнение

- Перед рискованным изменением сохраняй точное состояние эталона и при необходимости делай копию страницы.
- После каждого шага проверяй **результат действия**, а не только отправленную команду в браузере.
- Если редактор не сохранил правку — вернись к конкретному блоку, проверь состояние и повтори только нужное действие.
- Если публикация не произошла — это блокер; нельзя оформлять отчёт как «готово».
- Никогда не публикуй заметно сломанный визуальный результат «лишь бы был URL» без прямой команды пользователя.

## Антипаттерны

| Ошибка | Правильное поведение |
| --- | --- |
| Переписан дизайн с нуля | Дублируем согласованную страницу |
| Тексты вставлены сырой простынёй | Раскладываем по существующим секциям |
| Каталог сделан новым блоком | Добавляем карточку в существующую сетку |
| Страница сохранена, но не опубликована | Публикуем и проверяем публичный URL |
| Созданы десятки страниц до QA | Сначала проверяем один эталон типа |
| Исходная страница по ошибке изменилась | Работать на копии, сверять перед публикацией |
